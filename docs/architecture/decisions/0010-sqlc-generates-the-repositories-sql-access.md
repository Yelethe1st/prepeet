# ADR-0010: sqlc generates the repositories' SQL access

**Status:** Accepted  
**Owner:** olabode omoyele  
**Decision date:** 2026-08-24  
**Review date:** 2027-02-24  
**Supersedes:** the "Still open: `sqlc`" section of [ADR-0008](0008-go-library-baseline-net-http-and-an-in-repo-migration-runner.md)  
**Superseded by:** None

## Context

`sqlc` is named in the technology baseline of
[architecture-and-implementation-brief.md](../architecture-and-implementation-brief.md).
It was not used. [ADR-0008](0008-go-library-baseline-net-http-and-an-in-repo-migration-runner.md)
recorded that honestly rather than arguing against it after the fact: it had never been evaluated,
nothing about row-level security prevented it, and the repositories were hand-written `pgx` because
that was the quickest thing at the time.

That is the whole case for closing it. The two departures ADR-0008 does defend have arguments behind
them; this one had none, and a baseline that is followed where convenient is not a baseline.

## Decision

**Every query the service runs is written in a `queries.sql` file beside its module and the Go is
generated by `sqlc`.** Three modules have one: `internal/identity`, `platform/outbox`,
`platform/ratelimit`.

### One generated package per module, not one shared

A single package holding every table would let `identity` reach `tenancy`'s generated types, which
reopens by the back door the boundary [ADR-0005](0005-module-boundaries-and-extraction.md) closes.
Each module's block generates its own package, and `omit_unused_structs` keeps it to the tables its
own queries touch.

### Generated against the real migrations

`schema:` points at `platform/database/sql`, the same numbered files the migration runner applies.
The queries are therefore checked against the schema that will exist rather than against a
description of it, and a column renamed in a migration fails `make generate` rather than failing in
production. This is the property that makes the whole exercise worth more than type safety alone.

### The types are overridden to the domain's, not the driver's

`uuid` maps to `string` and `timestamptz` to `time.Time`, because the domain types, the service and
the OpenAPI contract are already written that way. Without the overrides every call site would
convert `pgtype.UUID` for no gain, since pgx encodes a Go string into `uuid` either way.

### What stays hand-written, and why it is structural

Each of these is impossible to generate rather than merely awkward. That distinction is the standard
the architecture test applies, and anything only awkward belongs in a `queries.sql`.

- **`SET LOCAL app.tenant_id` / `app.user_id`** in `platform/database`. `SET LOCAL` takes no bind
  parameters, so there is nothing for sqlc to type. It is also the one place a value is quoted into
  SQL, which is why it goes through a single audited helper rather than being written at call sites.
- **`SAVEPOINT` / `ROLLBACK TO` / `RELEASE`** in the slug retry. Transaction control, not a query.
- **`LISTEN`** in `platform/broadcast`. No parameters, and issued on a connection held open for
  notifications rather than through the pool.
- **`pg_notify`** in `platform/outbox`. It must travel inside the caller's transaction so the signal
  becomes visible exactly when the row does, which is the guarantee that package exists for.
- **The migration runner itself**, which creates and reads the table recording which migrations have
  run. No migration can describe that table, because it has to exist before the first one applies.

## Consequences

**The one dynamic query is gone.** `findSession` built its `WHERE` clause by concatenating a
predicate string, and callers passed one of two constants. sqlc cannot express that, so it became two
named queries. This is the clearest win of the migration and it was not the goal: an interpolated
predicate is a query no tool can check and one careless caller away from being where SQL is injected.

**Drift is a build gate.** `make generate` runs sqlc and `make check-generated` fails if the result
differs from what is committed, which is the gate the brief's CI baseline already required.

**Raw SQL in Go is now a test failure.** `TestSQLIsGeneratedRatherThanWritten` reads string literals
from the parsed source and refuses any statement outside the exemptions above. Literals rather than a
grep, because a comment explaining why a `SELECT` would be wrong is not a `SELECT`, and a rule that
cannot tell the two apart is one people learn to phrase around. Verified by smuggling a query into
the identity repository and confirming it fails, and by adding a comment containing `SELECT` and
confirming it does not.

**Costs accepted.** `nullif` and `coalesce` defeat sqlc's type inference, which produced `interface{}`
parameters named `Column4`; the queries now carry explicit casts and `sqlc.arg` names, which is more
verbose SQL and better documentation than the positional form was. Counts come back as `int32` and
are converted at three call sites. Each module gains a generated package.

## Reversibility

High. The generated code is ordinary `pgx` underneath, so abandoning sqlc means keeping the generated
files and deleting the config. What would be lost is the checking, not the ability to run.

## What would change this

- A query the planner needs built at runtime, such as a filter set chosen by the caller. sqlc has
  nothing for that, and the answer would be a query builder for those specific cases rather than a
  return to hand-written SQL everywhere.
- sqlc's inference failing on something that cannot be worked around with a cast, which would mean
  writing SQL for the tool rather than for the database.
