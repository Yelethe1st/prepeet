# User Journeys

**Status:** Proposed from product requirements and mockups  
**Owner:** Product and design  
**Last updated:** 2026-08-24

## First practice interview

```text
Marketing → Register → Verify email → Candidate routing
→ Profile basics → Configure interview → Consent and compose
→ Prepare/device check → Live interview → Finalize/process
→ Results/evidence → Review/coaching → Redo or next goal
```

Recovery branches: invalid document, composition failure, device failure, consent declined, provider outage, reconnect, partial media, delayed evaluation, insufficient evidence, and unassessable articulation.

## Returning practice candidate

```text
Login → Dashboard → Choose target/gap and personal requirements
→ Configure or reuse defaults → Prepare → Interview
→ Review requirement evidence and actions → Progression update
```

The dashboard must distinguish roles, disciplines, formats, rubrics, and criterion versions and never
average incomparable readiness or personal progress. Each recommendation identifies the prior private
practice observations that caused it.

## Screening candidate

```text
Invitation → Validate token → Resolve identity
→ Disclosure/consent/accommodations → Prepare/device check
→ Live screen → Submission receipt → Permitted status only
```

The candidate cannot reach practice results, coaching, employer evidence, notes, comparison, or decisions through URL manipulation.

## Recruiter invitation and review

```text
Create role/campaign → Select published configuration
→ Preview disclosure/email → Issue invitation
→ Monitor delivery/completion → Evaluation ready
→ Inspect evidence/coverage → Record human decision
→ Deliver approved integration event
```

## Re-review

```text
Candidate request or system flag → Validate eligibility
→ Assign independent reviewer if required → Freeze original inputs
→ Review evidence → Record outcome/rationale
→ Notify permitted parties → Append audit
```

## Tenant administration

```text
Invite member → Assign scoped capability → Configure policy
→ Draft rubric/calibration → Validate/approve/publish
→ Monitor usage/retention/integrations → Periodic access review
```

## Platform incident

```text
Alert/support report → Inspect aggregate health
→ Identify tenant/session under least privilege
→ Elevate with reason/ticket when necessary
→ Inspect workflow/provider/audit → Retry or remediate
→ Verify user recovery → Close incident/elevation
```

## Cross-journey state contract

Every data surface supports loading, empty, error, partial, forbidden, expired/revoked, delayed, insufficient evidence, unassessable input, reconnecting/recovered, and degraded incident where relevant.

Every error explains what failed, what remains safe, the permitted next action, and a reference ID. No timed interaction silently discards work.

## Journey validation backlog

- Review/results split comprehension.
- Insufficient-evidence comprehension.
- Evidence-first recruiter review and anchoring.
- Candidate trust in shared practice/screen branding.
- Real mobile network/media behavior.
- Assistive-technology and disabled-user testing.
- Multiple tenant and mixed-mode navigation.
